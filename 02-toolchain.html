The toolchain. Get a working environment, then never fight it again.

Chemistry libraries are unusual: they are thin Python wrappers around large C++ projects, which is why pip install has historically been a bad way to get them and why this field standardised on conda. This volume gets you installed, explains why the instructions are what they are, and covers the parts of NumPy and pandas that chemical data actually uses.

Part I

Getting it installed

Lesson 01

Why conda, not pip

Every tutorial tells you to use conda and none of them say why, which leaves you unable to judge when the advice stops applying. The reason is this:

The underlying situation

RDKit is a large C++ library. The Python package is a binding over it. So installing it is not "download some Python files" — it is "obtain a compiled binary that matches your operating system, your CPU architecture, and the exact versions of the C++ libraries it was linked against". The same is true of the crystallography, quantum chemistry and molecular dynamics tools you meet later.

Why that favoured conda

pip historically packaged Python code and left non-Python dependencies to you. conda packages anything, including compilers, C++ libraries and binary blobs, and it resolves versions across all of them together. For a stack that is mostly compiled code with Python on top, that difference was decisive.

What has changed, honestly

pip install rdkit now works on the common platforms, because the project publishes wheels. So for RDKit alone, pip is fine. conda still wins as soon as you add a second compiled tool — Open Babel, a docking engine, a quantum chemistry package — because that is where the version conflicts appear and where conda's solver earns its keep.

The recommendation

Use conda (via miniforge) for this course. It costs you ten minutes now and saves a day later, and it is what the job will use. Use pip inside the conda environment for pure-Python packages that conda does not carry.

miniforge, not Anaconda

Prefer miniforge — a minimal installer that defaults to the community conda-forge channel. The full Anaconda distribution is large, and its default channels carry licensing conditions for commercial use at organisations above a size threshold. miniforge sidesteps both. Wherever you see conda below, mamba is a drop-in replacement that resolves far faster, and miniforge ships it.

Lesson 02

The environment, step by step

  1. Install miniforge for your platform, then close and reopen your terminal so the conda command is on your path.
  2. Create an environment with a pinned Python. Do not install into base — you want to be able to delete and rebuild without losing conda itself.
  3. Install the chemistry stack in one command, so the solver sees all the constraints at once rather than being walked into a corner package by package.
  4. Register it as a Jupyter kernel, so notebooks can actually find it. Skipping this is the single most common reason a notebook reports "No module named rdkit" while the terminal imports it fine.
The four commands
# 1. create — pin Python; chemistry packages lag the newest release
conda create -n chem python=3.11 -y

# 2. activate
conda activate chem

# 3. install everything at once, from conda-forge
conda install -c conda-forge \
    rdkit pandas numpy scipy scikit-learn matplotlib seaborn \
    jupyterlab ipykernel py3dmol -y

# 4. make it visible to Jupyter
python -m ipykernel install --user --name chem --display-name "Python (chem)"
Two things that will cost you an afternoon

Pin the Python version. RDKit builds trail new Python releases by months. Ask for python=3.13 too early and conda will silently give you an RDKit from two years ago — or fail to solve with a wall of text that does not say that is the problem.

Install in one command, not four. Installing packages one at a time lets the solver commit to a version that blocks the next package. When that happens the error appears on the last package, which is never the one at fault.

Lesson 03

Proving it works

Worked example · the five lines that confirm everything

Run this. If it prints the three numbers, your environment is correct and you can stop thinking about installation.

from rdkit import Chem
from rdkit.Chem import Descriptors

mol = Chem.MolFromSmiles("CC(=O)Oc1ccccc1C(=O)O")   # aspirin
print(Chem.MolToSmiles(mol))                         # canonical form
print(Descriptors.MolWt(mol))                        # 180.159
print(mol.GetNumAtoms())                             # 13

Read what each line proved:

  • MolFromSmiles returned something other than None — the C++ parser loaded and ran. This is the real test.
  • MolToSmiles printed a SMILES that may not match what you typed. That is correct and important: RDKit rewrites it into its own canonical form. Volume 03 explains why that matters more than it looks.
  • MolWt gave 180.159, so the periodic table data loaded.
  • GetNumAtoms() gave 13, not 21 — hydrogens are implicit by default. Aspirin is C₉H₈O₄: 9 + 4 = 13 heavy atoms. Remember this, because "why does my atom count look wrong?" is a recurring beginner question.
Try it · Chem.MolFromSmiles("CC(=O)Oc1ccccc1C(=O)") returns None and prints a warning. What went wrong, and why does RDKit return None rather than raising?
Answer

The final oxygen is missing — the string ends C(=O) instead of C(=O)O. That leaves a carbon with an unfillable valence, so the molecule is chemically impossible and the sanitisation step rejects it.

It returns None rather than raising because you are usually parsing 100,000 molecules from a file and some of them are broken. An exception would abort the batch; None lets you count and log the failures and carry on. The consequence is the most important defensive habit in this field:

mol = Chem.MolFromSmiles(s)
if mol is None:
    bad.append(s)          # log it — never silently drop it
    continue

Every loop over SMILES needs this check. Without it you get AttributeError: 'NoneType' object has no attribute ... two hundred lines later, or worse, a dataset that quietly lost 3% of its rows.

Lesson 05

NumPy — the part chemistry actually uses

You need a narrow slice of NumPy, but you need it reflexively, because a fingerprint is a vector and a set of fingerprints is a matrix, and almost every similarity computation is one line of array arithmetic.

Worked example · similarity as arithmetic, done by hand

Tanimoto similarity between two bit vectors is: shared bits ÷ (bits in either). Here it is on toy 8-bit fingerprints, so you can see there is no magic in it.

import numpy as np

a = np.array([1,0,1,1,0,0,1,0])     # molecule A's fingerprint
b = np.array([1,0,1,0,0,1,1,0])     # molecule B's

shared = np.sum(a & b)              # bits ON in both      -> 3
either = np.sum(a | b)              # bits ON in either    -> 5
print(shared / either)              # 0.6

# the same for 2,000 molecules against one query, vectorised:
#   M is (2000, 2048), q is (2048,)
# shared = M @ q                      -> (2000,) via matrix product
# either = M.sum(1) + q.sum() - shared
# sims   = shared / either            -> all 2,000 similarities, no loop

The second block is the lesson. The loop version of that takes seconds per thousand molecules; the matrix version takes milliseconds. When Volume 09 screens two million compounds, this is the difference between a coffee break and an overnight job — and the formulation is identical, just applied to a matrix instead of a pair.

Lesson 06

pandas for chemical tables — and the trap in it

A chemical dataset is a DataFrame with a SMILES column. That much is obvious. What is not obvious is how easily a round trip through a file corrupts it.

The trap: pandas, CSVs and chemistry do not fully agree
  • A compound ID like 001234 becomes the integer 1234 on read. Leading zeros are gone, and the join against the assay file now silently misses.
  • A SMILES containing a comma — they exist, inside brackets — breaks a naive CSV split.
  • Excel is worse. It will convert compound codes that look like dates, and it mangles long numbers into scientific notation. Never let a chemical file pass through Excel on its way to your model.
  • A missing activity value read as the string "NA" turns the whole column into text, and then your model trains on nothing useful.

The habits: read IDs as strings explicitly (dtype={'id': str}), prefer tab-separated or Parquet over CSV, and assert the row count and the parse-success count after every load.

Worked example · a defensive load 
import pandas as pd
from rdkit import Chem

df = pd.read_csv("compounds.csv", dtype={"compound_id": str})
print(f"loaded {len(df)} rows")

df["mol"] = df["smiles"].apply(Chem.MolFromSmiles)

bad = df["mol"].isna().sum()
print(f"{bad} of {len(df)} SMILES failed to parse")
if bad / len(df) > 0.02:
    raise ValueError("more than 2% unparseable — check the file, do not proceed")

df = df[df["mol"].notna()].copy()

The threshold is the point. A few failures are normal. Twenty percent means you are reading the wrong column, or the file uses a different format, or the encoding is wrong — and finding that out now is much cheaper than explaining a bad model later. Lesson 07

Plots that tell the truth about chemical data

Two rules cover most of it, and both come from the shape chemical data tends to have:

Log-scale almost everything

Potencies, solubilities and concentrations span orders of magnitude. On a linear axis, every compound worth looking at is crushed into the bottom 2% of the plot. This is why the field converts IC₅₀ to pIC₅₀ before doing anything — it makes the quantity approximately normal and plottable.

Show the distribution, not the summary

A bar chart of mean activity per series hides that one series is bimodal — which usually means two binding modes, or two assays merged, and is the most interesting thing in the data. Use a strip plot or a box plot with points overlaid.

One chemistry-specific habit

Always be able to get from a point on a plot back to the molecule. An outlier is not noise to be trimmed — it is a compound, with a structure, and looking at it is how you discover that your data has a problem or your project has a finding. Keep the index aligned, and prefer plotting tools that let you hover for the structure.

Part III

Working habits

Lesson 08

Notebooks, and the specific way they lie

Notebooks are right for this work — you are looking at molecules, and seeing structures inline is genuinely valuable. But they have one failure mode that matters more in science than elsewhere:

The problem

The visible order of cells is not the order they ran in. A notebook showing a clean result may depend on a cell you edited after running it, or deleted. The document looks like a record of what happened and is not one.

Why it is worse here

Because the output is the claim. "This model achieves an AUC of 0.83" gets copied into a slide, then into a decision about what to synthesise. If the number came from a stale variable, nobody will ever find out.

The three habits that fix it
  • Restart and run all before you believe any number you intend to report. Not occasionally — every time.
  • Move anything reused into a .py module and import it. Functions in a notebook are copied; functions in a module are shared and testable.
  • Notebooks explore; scripts produce. Once a pipeline works, it moves into a script that runs start to finish with no human in it.
Lesson 09

A project layout that survives contact

  project/
    data/
      raw/            <-- exactly as downloaded. NEVER edited. Read-only.
      interim/        <-- parsed, standardised, still one row per source record
      processed/      <-- model-ready; the file the training script actually opens
    notebooks/        <-- numbered, exploratory, disposable
    src/
      data.py         <-- loading and curation
      features.py     <-- descriptors and fingerprints
      models.py       <-- training and evaluation
      splits.py       <-- scaffold splitting  (its own file — you will reuse it everywhere)
    models/           <-- saved models, each with its metrics and data version beside it
    reports/
      figures/
    environment.yml   <-- the exact environment, exported
    README.md         <-- what the model does, and what it does NOT cover

  THE RULE THAT MATTERS MOST:  data/raw/ is immutable.
    Every cleaning decision is a step in code from raw -> interim -> processed,
    so that six months later you can answer "why is this compound missing?"
    by reading the pipeline instead of guessing.
Lesson 10

Making it reproducible — the chemistry-specific parts

Standard reproducibility advice applies: pin versions, set seeds, version the data. Three things are specific to this field and are the ones people forget:

Pin this tooBecause
The RDKit versionDescriptor implementations and aromaticity perception have changed between releases. The same molecule can get a different fingerprint from a different RDKit, which silently invalidates a saved model. Record it next to the model, always.
The exact fingerprint parametersA Morgan fingerprint is defined by its radius and bit length. A model trained on radius 2 / 2048 bits and served radius 3 / 1024 bits will not error — it will just be wrong. Store the parameters with the model, not in a separate notebook.
The standardisation recipeWhether you stripped salts, neutralised charges, and which tautomer rule you used, changes what the molecule is. Two people with the same raw file and different recipes get different models. Volume 06 makes this a named, versioned step.
The one-line summary of this lesson

A saved model is not a file, it is a file plus the recipe that made its inputs. Save them together and you can trust a prediction a year later. Save the model alone and you have a function whose input format you will eventually guess wrong.

When it breaks — the five common failures

SymptomCause and fix
ModuleNotFoundError: rdkit in a notebook, but it imports fine in the terminalThe notebook is running a different kernel. Register the environment (step 4 of Lesson 02) and select it from the kernel menu.
conda hangs for many minutes on "Solving environment"Too many loose constraints, or mixed channels. Use mamba, stick to conda-forge alone, and pin Python.
AttributeError: 'NoneType' has no attribute 'GetNumAtoms'A SMILES failed to parse and you did not check for None. Add the guard from Lesson 03.
Molecules render as blank boxes in JupyterDrawing needs from rdkit.Chem.Draw import IPythonConsole imported once to register the renderer.
Descriptor values differ from a colleague's on the same moleculeDifferent RDKit versions, or one of you standardised and the other did not. Compare canonical SMILES first — if those differ, the molecules differ.
