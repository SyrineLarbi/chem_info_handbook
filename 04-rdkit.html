Part I

The Mol object

Lesson 01

What a Mol actually is

A Mol is a graph with chemistry attached. Concretely it holds:

  Mol
   |
   +-- ATOMS          an ordered list. Each has an INDEX (0, 1, 2, ...)
   |                  element, charge, aromatic flag, implicit H count,
   |                  chirality, isotope, and arbitrary properties you attach
   |
   +-- BONDS          each joins two atom indices; has a type (single/double/
   |                  triple/aromatic) and its own stereo information
   |
   +-- RING INFO      computed during sanitisation, not stored in the input
   |
   +-- CONFORMERS     zero or more sets of 3D coordinates. A Mol from SMILES
   |                  has NONE until you generate them.
   |
   +-- PROPERTIES     name/value pairs. This is where SDF data fields land.

  ⭐ THE ATOM INDEX IS THE KEY TO EVERYTHING.
     Substructure matches return indices. Fingerprint bits map back to
     indices. Atom attribution in a neural network returns indices.
     Learn to think in them.
Atom indices are stable within a Mol, not across Mols

Atom 3 of one molecule has nothing to do with atom 3 of another. More subtly: parse the same molecule from two different SMILES strings and you get two different index orders, because the index follows the order the string was written. If you need indices to be comparable, canonicalise first — then the ordering is deterministic.

Lesson 02

Atoms and bonds — iterating over a molecule

Worked example · walking aspirin atom by atom 
from rdkit import Chem

mol = Chem.MolFromSmiles("CC(=O)Oc1ccccc1C(=O)O")

for atom in mol.GetAtoms():
    print(atom.GetIdx(),              # 0, 1, 2, ...
          atom.GetSymbol(),           # 'C', 'O'
          atom.GetIsAromatic(),       # True inside the ring
          atom.GetDegree(),           # number of heavy-atom neighbours
          atom.GetTotalNumHs())       # implicit + explicit hydrogens

  0 C False 1 3        <-- the methyl carbon: one neighbour, three H
  1 C False 3 0        <-- the carbonyl carbon: three neighbours, no H
  2 O False 1 0        <-- the =O
  3 O False 2 0        <-- the ester oxygen
  4 c True  3 0        <-- ring starts; aromatic, no H (it carries the ester)
  5 c True  2 1        <-- aromatic CH
  ...

# bonds
for bond in mol.GetBonds():
    print(bond.GetBeginAtomIdx(), bond.GetEndAtomIdx(),
          bond.GetBondType())         # SINGLE, DOUBLE, AROMATIC

# neighbours of a specific atom
for nbr in mol.GetAtomWithIdx(1).GetNeighbors():
    print(nbr.GetIdx(), nbr.GetSymbol())

Read the GetTotalNumHs() column. Atom 0 reports 3 hydrogens even though none appeared in the SMILES — they are implicit, inferred from valence. This is why the atom count was 13 and not 21 back in Volume 02, and it is the source of a whole class of bugs covered in the gotchas below.

Lesson 03

Sanitisation — the step you did not ask for

When MolFromSmiles runs, it does not simply parse. It then sanitises, and understanding that step explains most surprising behaviour.

Sanitisation doesWhich means
Valence checkingAn impossible molecule is rejected — this is why you get None rather than a broken object.
Aromaticity perceptionRings are analysed and flagged aromatic. This is why Kekulé and aromatic input converge (Volume 03, Lesson 02).
Ring informationThe smallest set of rings is computed. GetRingInfo() does not work before this.
Implicit hydrogen countsFilled in from valence rules. Everything about H counts depends on it.
Stereochemistry assignmentChiral tags are resolved into a consistent internal form.
When you need to turn it off

Occasionally you need a molecule that fails valence rules — an intermediate, a fragment with an open valence, a badly drawn record you want to inspect rather than discard. Then:

mol = Chem.MolFromSmiles(smi, sanitize=False)
mol.UpdatePropertyCache(strict=False)     # minimal setup so it is usable
Chem.SanitizeMol(mol, Chem.SanitizeFlags.SANITIZE_ALL ^
                      Chem.SanitizeFlags.SANITIZE_PROPERTIES)   # selective

Use this rarely and deliberately. An unsanitised Mol will silently misbehave in fingerprinting and descriptor code that assumes ring info exists.

Part II

Reading and writing

Lesson 04

In and out of every format

The conversion table, as code
from rdkit import Chem

# ---- IN ----
Chem.MolFromSmiles("CCO")              # SMILES  -> Mol
Chem.MolFromSmarts("C(=O)[OH]")        # SMARTS  -> query Mol  (NOT for real molecules)
Chem.MolFromMolFile("x.mol")           # MOL     -> Mol
Chem.MolFromMolBlock(block_string)     # MOL text in memory
Chem.MolFromInchi("InChI=1S/C2H6O/...")
Chem.MolFromPDBFile("protein.pdb")

# ---- OUT ----
Chem.MolToSmiles(mol)                  # ALWAYS canonical
Chem.MolToInchi(mol)
Chem.MolToInchiKey(mol)                # the 27-char database key
Chem.MolToMolBlock(mol)                # needs coordinates to be useful

# ---- THE ONE-LINE IDIOM YOU WILL USE CONSTANTLY ----
canonical = Chem.MolToSmiles(Chem.MolFromSmiles(raw_smiles))
MolFromSmarts is not MolFromSmiles

A Mol built from SMARTS is a query. It has no implicit hydrogens, no sanitised aromaticity, and no valid chemistry. Passing one to a descriptor function returns nonsense rather than an error. Use it only as the second argument to a substructure call — and name the variable pattern or query so you never confuse the two.

Lesson 05

Reading files at scale

Worked example · a 100,000-compound SDF, safely 
from rdkit import Chem

# SDMolSupplier is LAZY — it does not load the file into memory.
supplier = Chem.SDMolSupplier("screening_library.sdf")

good, failed = [], 0
for i, mol in enumerate(supplier):
    if mol is None:                  # <-- the record failed to parse
        failed += 1
        continue
    good.append(mol)

print(f"{len(good)} parsed, {failed} failed, {i+1} records total")

# the data fields from the SDF are on the molecule:
print(good[0].GetPropsAsDict())
#   {'compound_id': 'CHEMBL25', 'IC50_nM': 120.0, 'assay_id': '...'}
print(good[0].GetProp("compound_id"))

Three things in that snippet are load-bearing:

  • SDMolSupplier is an iterator. Calling list(supplier) on a large file loads every molecule at once and can exhaust memory — iterate instead.
  • The None check is not optional. Real vendor SDFs contain broken records. Counting them is how you notice the file is 8% junk.
  • GetPropsAsDict() on the first record before writing any other code, so you see what the field names actually are. They are never what the email said.

For gzipped files use Chem.ForwardSDMolSupplier(gzip.open(path)) — forward-only, no random access, but it streams.

Part III

Doing things to molecules

Lesson 06

Substructure search

The three calls
pattern = Chem.MolFromSmarts("c1ccccc1")          # any benzene ring

mol.HasSubstructMatch(pattern)      # -> True/False        (fast; use for filtering)
mol.GetSubstructMatch(pattern)      # -> (4,5,6,7,8,9)     FIRST match, as atom indices
mol.GetSubstructMatches(pattern)    # -> ((4,5,...), ...)  ALL matches

# filtering a library — the most common use in practice
has_ring = [m for m in mols if m.HasSubstructMatch(pattern)]
The symmetry surprise

GetSubstructMatches on a symmetric pattern returns many matches for what looks like one — benzene against benzene gives 12, one for each way of mapping the ring onto itself. If you are counting occurrences of a group, pass uniquify=True (the default) and still sanity-check the number, or count distinct matched atom sets rather than matches.

Lesson 07

Editing molecules — and stripping salts

Worked example · the desalting you will run on every dataset

Vendor data is full of salts: CC(=O)O.[Na+] is the sodium salt of acetic acid. For modelling you almost always want the organic part alone.

from rdkit.Chem.MolStandardize import rdMolStandardize

remover = rdMolStandardize.LargestFragmentChooser()

for smi in ["CC(=O)[O-].[Na+]",              # sodium acetate
            "CC(=O)Oc1ccccc1C(=O)O",         # aspirin, no salt
            "c1ccccc1N.Cl"]:                 # aniline hydrochloride
    mol = Chem.MolFromSmiles(smi)
    clean = remover.choose(mol)
    print(smi, "->", Chem.MolToSmiles(clean))

  CC(=O)[O-].[Na+]         -> CC(=O)[O-]
  CC(=O)Oc1ccccc1C(=O)O    -> CC(=O)Oc1ccccc1C(=O)O
  c1ccccc1N.Cl             -> Nc1ccccc1

Note the first result still carries a negative charge. Largest-fragment selection removes the counterion but does not neutralise what is left. A full standardisation adds an uncharging step:

uncharger = rdMolStandardize.Uncharger()
clean = uncharger.uncharge(remover.choose(mol))     # -> CC(=O)O

Volume 06 assembles these into the complete curation pipeline, in the right order, with the decisions that go with them.

Try it · LargestFragmentChooser is a heuristic. Name a case where "the largest fragment" is the wrong answer.
Answer

A co-crystal or a salt where the counterion is bigger than the active molecule. A small amine paired with a large organic acid — or a drug formulated as a salt of something like pamoic acid — gets the wrong half kept.

The second case: genuine multi-component actives. Some drugs are two molecules, and discarding one changes what the row means.

The practical defence is not a better heuristic — it is counting how many rows changed and inspecting a sample by eye. If 40% of your dataset was altered by desalting, something other than salt-stripping is happening and you want to know what before you train on it.

Lesson 08

Scaffolds — the concept Volume 08 depends on

A Murcko scaffold is what remains when you strip every side chain and keep the ring systems plus the linkers joining them. It is the field's standard answer to "what family is this molecule from?"

Worked example · scaffolds of the course molecules 
from rdkit.Chem.Scaffolds import MurckoScaffold

for name, smi in [("aspirin",     "CC(=O)Oc1ccccc1C(=O)O"),
                  ("paracetamol", "CC(=O)Nc1ccc(O)cc1"),
                  ("caffeine",    "Cn1cnc2c1c(=O)n(C)c(=O)n2C")]:
    mol = Chem.MolFromSmiles(smi)
    scaf = MurckoScaffold.GetScaffoldForMol(mol)
    print(f"{name:14s} -> {Chem.MolToSmiles(scaf)}")

  aspirin        -> c1ccccc1
  paracetamol    -> c1ccccc1
  caffeine       -> O=c1[nH]cnc2[nH]cnc12   (its fused ring core)

Aspirin and paracetamol share a scaffold. That is the point — they are both "a benzene ring with things on it", so a model that has seen one has seen something structurally related to the other. Putting one in training and the other in test does not test generalisation. Volume 08 turns this observation into the scaffold split.

It also shows the limitation: c1ccccc1 is such a common scaffold that it groups together molecules with nothing else in common. Scaffold splitting is a useful discipline, not a perfect one.

Lesson 09

Reactions — transforming molecules by rule

RDKit can apply a reaction written in SMARTS reaction notation (reactants>>products) to generate products. This is the machinery behind enumerating analogues and behind retrosynthesis in Volume 11.

Worked example · esterification, applied 
from rdkit.Chem import AllChem

# "an acid plus an alcohol gives an ester"
rxn = AllChem.ReactionFromSmarts(
    "[C:1](=[O:2])[OH].[OH][C:3]>>[C:1](=[O:2])O[C:3]")

acid    = Chem.MolFromSmiles("CC(=O)O")      # acetic acid
alcohol = Chem.MolFromSmiles("CCO")          # ethanol

products = rxn.RunReactants((acid, alcohol))
for p in products:
    print(Chem.MolToSmiles(p[0]))            # CCOC(C)=O   (ethyl acetate)

The numbers are atom maps. [C:1] on the left and [C:1] on the right are the same atom — that is how RDKit knows which atoms survive the transformation and carry their substituents along. Without the maps, the reaction cannot be applied to a real molecule.

Two cautions. RunReactants returns a tuple of tuples, because one reaction may match several places and each match may give several products — always iterate. And the products come back unsanitised, so call Chem.SanitizeMol before using them for anything.

Lesson 10

Drawing

Three things worth knowing
# 1. INSIDE A NOTEBOOK — import once, then molecules render automatically
from rdkit.Chem.Draw import IPythonConsole
mol                                  # just evaluating it draws it

# 2. A GRID OF MOLECULES — the single most useful call in the library
from rdkit.Chem import Draw
Draw.MolsToGridImage(mols[:12],
                     molsPerRow=4,
                     subImgSize=(250, 200),
                     legends=[m.GetProp("_Name") for m in mols[:12]])

# 3. HIGHLIGHTING A MATCH — showing WHY a filter fired
pattern = Chem.MolFromSmarts("C(=O)[OH]")
hit = mol.GetSubstructMatch(pattern)
Draw.MolToImage(mol, highlightAtoms=hit)
Why the grid image matters more than it seems

Looking at molecules is the debugging method of this field. A distribution plot tells you something is wrong; a grid of the twelve worst-predicted compounds tells you what — that they are all the same series, or all contain a group your descriptors miss, or that four of them are the same compound drawn differently. Build the habit of drawing the outliers before theorising about them.

Reference

Ten gotchas, each worth a day

#The mistakeWhat actually happens
1Not checking MolFromSmiles for NoneAttributeError far from the cause, or silently lost rows.
2Comparing input SMILES strings directlyDuplicates survive. Always canonicalise first.
3Expecting GetNumAtoms() to include hydrogensIt counts heavy atoms. Use Chem.AddHs(mol) first if you need them.
4Generating 3D coordinates without adding hydrogensThe geometry is wrong. AddHs before EmbedMolecule, always.
5Using MolFromSmarts output as a real moleculeDescriptors return nonsense, with no error.
6Assuming atom indices match between two parsesThey follow input order. Canonicalise if you need stability.
7list(SDMolSupplier(...)) on a large fileMemory exhaustion. Iterate.
8Forgetting that RunReactants returns unsanitised productsDownstream calls misbehave in ways that look like data problems.
9Trusting GetSubstructMatches counts on symmetric patternsTwelve matches for one benzene ring.
10Silencing RDKit's warning logYou stop seeing "could not sanitise" messages that were telling you the file is bad. Capture them instead: RDLogger.logger().setLevel(RDLogger.ERROR) only after you have read them once.

Lesson 11

R-group decomposition — the table chemists actually want

A medicinal chemistry series is one core with things hung off it. R-group decomposition splits every molecule in the series into that shared core plus its substituents, which turns a list of SMILES into the table a chemist reasons with.

Worked example · from a list of molecules to an SAR table 
from rdkit.Chem import rdRGroupDecomposition as rgd

core = Chem.MolFromSmarts("c1ccc2[nH]ccc2c1")     # the shared scaffold
groups, unmatched = rgd.RGroupDecompose([core], mols, asSmiles=True)

WHAT COMES BACK

   Core              R1        R2      pIC50
   ---------------------------------------------
   indole core       -CH3      -H       6.2
   indole core       -CH2CH3   -H       6.4
   indole core       -CF3      -H       7.9      <- fluorine helps
   indole core       -CH3      -OMe     6.1
   indole core       -CF3      -OMe     7.8      <- and it is additive

⭐ WHY THIS IS THE MOST USEFUL OUTPUT IN MEDICINAL CHEMISTRY
   A model says "predicted 7.4". This table says "-CF3 at R1 is
   worth about 1.5 log units, and R2 does almost nothing." The
   second is a sentence a chemist can act on tomorrow, and it
   needed no model at all.

⚠ THE PART THAT GOES WRONG
   `unmatched` is not an error list to ignore — it is the
   molecules that do not contain your core. Either your core
   is drawn too specifically, or the series is not one series.
   Both are findings. Always print len(unmatched).
